## 会话与完成信号

空闲时确认来源可用，记录原输入源、App及窗口，固定本次配置快照，再发送一次厂商语音键。停止或取消后等待厂商完成，随后恢复日常输入源并处理暂存输入。

豆包从启动前窗口基线中识别本次新增窗口，稳定消失0.2秒后推动恢复。录音阶段允许持续等待，收到停止信号后最长等待60秒。第二次RimeDou触发会在本次窗口仍存在时发送一次停止键，厂商原生停止则沿窗口完成流程处理。未获得窗口观测时沿用按键结束及配置的恢复延迟。

千问启动时要求可确认的窗口状态，观察到本次窗口后才确定停止方向。显式停止后等待窗口稳定消失，默认稳定期0.15秒，完成等待上限60秒。

## 千问Esc取消

单独Esc作为明确取消意图交给千问，完整按下/松开、长按重复及迟到松开沿原手势处理，补发队列中Esc事件数为0。只收到松开时仍可识别取消。刚启动时保留取消意图，再结合窗口与输入源确认恢复。已进入保护后的取消也按当前状态核对。

取消恢复发起时退役该意图，恢复失败后保留用户处理入口。缺少取消意图的意外窗口消失以及未知窗口、未知输入源走保护路径。

## 输入暂存与恢复

等待识别和恢复时，键盘事件暂存在内存。补发需确认日常输入源、原App及窗口，并等待完整手势释放。重放投递原App进程，AX目标捕获安排在全局键盘回调之外。空暂存会话结束时退役旧触发手势。

恢复普通输入源后，补发条件持续5秒仍未满足会暂停监听并保留暂存。用户可以回原窗口继续补发，或确认语音已结束后选择“确认语音已结束，丢弃暂存并恢复快捷键”。该动作核对窗口、输入源和发送状态，必要时主动恢复原日常输入法，再完成明确弃存和监听重启。默认恢复期限约4秒，失败或状态变化会给出提示并保留暂存。异步恢复用操作标识隔离旧回调。

会话结束后短期观察输入源被厂商再次抢占的情况，并按已有次数与时限纠正。单独合成Shift可能切换RIME中英文，修改输入上下文绑定时应验证该副作用。

## 单来源与配置

按当前启用的来源校验冲突。启用集合变化后，在安全空闲时重读原始JSON并重新建立监听；会话中沿用其启动快照。配置支持旧字段，生成配置使用新名称，详见[配置说明](configuration.md)。

## 验证与构建

```bash
swift test
swift build -c release
./scripts/build-app.sh
```

打包读取`support/Info.plist`与`assets/AppIcon.icns`，输出`build/rimedou.app`。保护分支变更优先扩展现有模拟回归。发布前同时核对[人工验收](manual-testing.md)和[验证记录](validation.md)。

启动请求、窗口状态、厂商接收和用户实际结果各自记录其证明范围。运行时窗口查询使用窗口ID、进程身份及可见边界，诊断日志只保存必要状态元数据。
